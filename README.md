# 简介

这是参加WaytoAGI的[1024黑客松活动](https://1024.waytoagi.com/)做出来的项目。活动大约两天，消耗了大约300刀的token做出来的。

活动分为六个赛道，每个参与者可以提交最多两个赛道。其中有：基于麦当劳MCP的点餐、OPC、工作台、侦探、游戏和短剧。

## 灵感来源

当时听完介绍后，我想到了可以结合游戏和麦当劳的点餐，做一个用游戏的方式来点餐的项目。

另外一个灵感来源是，活动这段时间，AI逆向的新闻很火，而《塞尔达传说》也刚刚被逆向出来。所以当时的想法就是，能不能通过改mod的方式，让《塞尔达传说》里的做饭系统，变成做麦当劳的菜品。

改mod时间肯定不够，而且还有版权的风险。所以我打算用最强的模型，来『抄』一个塞尔达。

## 玩法

### 做出第一份料理

1. 点击「开始冒险」，进入「初见之森」料理营地。
2. 按 `Tab` 打开背包。初始每种食材有 **50 份**，可以直接尝试搭配，也可以先到营地周围拾取补给。
3. 点击食材拿取，最多同时手持 **5 份**，同一种食材可以重复拿取。点击手持栏中的材料可放回。
4. 关闭背包，走近营地的料理锅。看到「烹饪」提示后，按 `E` 或点击交互按钮。
5. 等待料理动画与菜单匹配完成，查看成品。首次做出的菜品会加入「料理手记」，后续再做会累积完成次数。
6. 点击「继续冒险」返回营地，尝试其他组合，发现全部 **14 种料理**。

料理动画约 5.6 秒；如果菜单查询尚未完成，会继续等待。等待时可点击「取回食材」。查询失败也会归还食材，可以重试。

营地食材拾取后约 **45 秒**补充。库存、料理发现记录、完成次数和声音设置保存在当前浏览器的 `localStorage` 中；清理站点数据会清除这些游戏进度。

### 料理搭配示例

下面是每种料理的一组可用搭配，食材名称使用背包中的显示名称：

| 料理               | 食材组合                                      |
| ------------------ | --------------------------------------------- |
| 汉堡包             | 芝麻面包 + 厚切牛肉                           |
| 吉士汉堡包         | 芝麻面包 + 厚切牛肉 + 金色芝士                |
| 双层吉士汉堡       | 芝麻面包 + 厚切牛肉 × 2 + 金色芝士            |
| 巨无霸             | 芝麻面包 + 厚切牛肉 × 2 + 翠叶生菜 + 酸脆黄瓜 |
| 芝士安格斯厚牛堡   | 芝麻面包 + 厚切牛肉 + 金色芝士 + 红熟番茄     |
| 麦香鸡             | 芝麻面包 + 酥嫩鸡肉 + 翠叶生菜                |
| 麦辣鸡腿汉堡       | 芝麻面包 + 酥嫩鸡肉 + 火焰辣酱                |
| 板烧鸡腿堡         | 芝麻面包 + 酥嫩鸡肉 + 烤味酱                  |
| 麦香鱼             | 芝麻面包 + 鲜香鱼排 + 金色芝士                |
| 原味双层深海鳕鱼堡 | 芝麻面包 + 鲜香鱼排 × 2 + 金色芝士            |
| 麦乐鸡5块          | 酥嫩鸡肉                                      |
| 麦辣鸡翅2块        | 酥嫩鸡肉 + 火焰辣酱                           |
| 中薯条             | 金脆薯条                                      |
| 马苏里拉拉丝芝士条 | 金色芝士                                      |

食材组合用于匹配菜品，**实际餐品统一采用标准规格、标准配方**，不支持大小份、去酱或额外添加配料。重复拿取薯条也不会变成大份。

混合肉类时，以数量最多的肉类为主；数量相同则以最后加入的肉类为主。规则按优先级匹配，例如两份牛肉加生菜优先对应巨无霸。只放面包、蔬菜或酱料会提示补充主料。

真实模式还会根据当前门店的可售菜单确认成品；目标菜品不可售时，只在预设的同类候选中回退，并说明差异。完整映射见 [食材与 MCP 菜品映射](docs/ingredient-mcp-mapping.md)，规则定义在 `src/game/data.ts` 的 `RECIPE_RULES` 中。

### 从料理进入点餐

在结果页点击「在麦当劳点这份料理」，获取价格，核对商品与标准配方，再选择取餐方式并确认。

- **演示模式**：门店、菜单与价格为测试数据，只创建本地 `DEMO-...` 订单。
- **真实模式**：确认后创建真实待支付订单，再通过返回的麦当劳支付入口完成支付。单纯烹饪、查看结果或获取价格不会创建订单。

当前支持到店、立即取餐和一份标准配方单品，暂不支持外送、预约、优惠券、套餐自选或配料定制。报价有效期为 5 分钟，超时后需要重新获取。

## 快速启动

需要 **Node.js 22.12+**、npm，以及支持 WebGL 的现代浏览器。在项目根目录执行：

```sh
npm ci
cp .env.example .env
npm run dev
```

如果已有 `.env`，直接修改现有文件，跳过复制步骤。首次体验请确认其中是 `MCD_MODE=demo`；演示模式不需要 MCP Token，也不会产生真实订单或扣款。

启动后打开 **http://127.0.0.1:5173**。

`npm run dev` 同时启动两个服务：

| 服务        | 默认地址                | 用途                 |
| ----------- | ----------------------- | -------------------- |
| Vite 网页   | `http://127.0.0.1:5173` | 游戏页面与前端热更新 |
| Express API | `http://127.0.0.1:3001` | 料理匹配、报价和订单 |

开发时网页通过 Vite 代理访问 `/api`，因此体验完整玩法需要两个服务一起运行。

## 接入真实 MCP

在 `.env` 中设置：

```dotenv
MCD_MODE=live
MCD_MCP_URL=https://mcp.mcd.cn
MCD_MCP_TOKEN=你的官方Token
MCD_MCP_MAPPING_PATH=server/mcp.mapping.json
```

Token 仅由服务端读取；不要添加 `VITE_` 前缀或提交 `.env`。修改配置后重启服务。

游戏后台默认固定使用 **广州滨江东路嘉仕花园餐厅**，门店编码为 `1400916`。该店未营业、搜索不到或菜单不可用时会提示重试，不会自动切换到其他门店。需要更换门店时，一起配置以下三个变量：

```dotenv
MCD_STORE_CITY=广州
MCD_STORE_KEYWORD=滨江东路嘉仕花园
MCD_STORE_CODE=1400916
```

接入后可执行只读检查：

```sh
# 查看 MCP 工具清单
npm run mcp:inspect

# 检查门店、菜单、详情及算价链路，不创建订单
npm run mcp:check -- 广州 滨江东路嘉仕花园
```

`mcp:check` 按命令参数搜索并选取营业门店，用于验证连接；游戏实际使用的固定门店仍由上述环境变量决定。

真实创建订单流程已经实现并通过模拟 MCP 测试，但尚未验证真实下单。订单持久化、重复提交保护和未知状态处理详见 [服务端说明](server/README.md)。

## 构建与运行

```sh
npm run build
npm start
```

构建先执行 TypeScript 检查，再生成 `dist/`。`npm start` 启动 API，并在存在构建产物时提供游戏静态页面，默认访问 **http://127.0.0.1:3001**。

默认监听地址为 `127.0.0.1`，端口为 `3001`，可通过 `.env` 中的 `HOST`、`PORT` 修改。若修改开发 API 端口，还需同步修改 `vite.config.ts` 中的代理目标。

当前订单服务面向本地或受控的单实例运行，没有用户账号及按用户隔离的订单权限。公开多人部署前需要补充认证、权限隔离、共享存储和限流。

### 常用命令

| 命令                 | 用途                               |
| -------------------- | ---------------------------------- |
| `npm run dev`        | 同时启动游戏和 API，支持开发热更新 |
| `npm run dev:client` | 单独启动 Vite 网页                 |
| `npm run dev:server` | 单独启动 API，监听代码变化         |
| `npm run typecheck`  | 只检查 TypeScript 类型             |
| `npm test`           | 运行游戏逻辑、API 与模拟 MCP 测试  |
| `npm run build`      | 类型检查并构建网页                 |
| `npm start`          | 启动服务端并提供已有的网页构建产物 |
| `npm run preview`    | 仅预览网页构建产物，不启动 API     |

测试不读取 `.env` Token，不连接真实 MCP，也不会创建真实订单。订单记录默认写入 `server/data/orders.json`，可用 `MCD_LEDGER_PATH` 修改；它与浏览器中的游戏存档分开保存。

## 项目结构

```text
src/
  App.tsx                游戏入口、界面与快捷键
  game/                  食材与食谱、状态、存档、声音和 API 调用
  scene/                 3D 营地、角色、料理锅与食物模型
  ui/                    背包、手记、料理结果、订单与小地图
server/
  index.ts               服务启动与环境配置
  app.ts                 API 路由及报价、订单流程
  automatic-menu.ts      后台门店选择与菜单获取
  cooking.ts             食材与可售商品匹配
  demo.ts                本地演示适配器
  mcp.ts                 官方 MCP 适配器
  mcp.mapping.json        工具参数及菜品映射
  ledger.ts              持久化订单记录与去重
tests/                   游戏与服务端测试
docs/                    映射规则、研究记录与 Graphify 说明
resource/sound/           游戏音频与素材来源说明
```

前端使用 React 19、TypeScript、Vite、Three.js、React Three Fiber / Drei 和 Zustand；服务端使用 Express 5 与 MCP SDK。

代码关系图是可选的开发辅助工具，安装和查询方法见 [Graphify 说明](docs/graphify.md)，不影响游戏启动。音频使用情况与来源见 [音频素材说明](resource/sound/README.md)。
