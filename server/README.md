# 料理订单服务

服务通过 MCP SDK 的 Streamable HTTP 连接麦当劳官方服务。已用真实连接验证工具发现、门店搜索、菜单、餐品详情和算价；创建订单流程已实现并通过模拟服务测试，**未执行真实下单**。

当前支持到店取餐、立即取餐、一份标准配方单品。暂不支持外送、预约、优惠券、自选特调或套餐选配。取餐方式由本次算价返回，用户需要明确选择。

## 本地演示

`.env.example` 默认 `MCD_MODE=demo`。已配置的本机 `.env` 使用真实模式；如需演示，将其切换为 `demo` 后重启。`npm run dev` 同时启动网页与 API，网页地址为 `http://127.0.0.1:5173`。单独运行 API 使用 `npm run dev:server`，默认监听 `127.0.0.1:3001`。`npm run build` 后，`npm start` 同时提供 `dist` 静态文件与 API。

演示菜单、门店和价格均为游戏测试数据。`/api/orders` 返回 `DEMO-...` 订单号，不访问麦当劳、不产生真实订单，也不提供伪造支付链接。

## 接通真实 MCP

1. 新环境中复制根目录 `.env.example` 为 `.env`，设置以下变量。已有 `.env` 时直接修改，避免覆盖 Token：

   ```dotenv
   MCD_MODE=live
   MCD_MCP_URL=https://mcp.mcd.cn
   MCD_MCP_TOKEN=你的官方Token
   MCD_MCP_MAPPING_PATH=server/mcp.mapping.json
   ```

   Token 仅由服务端读取，不要使用 `VITE_` 前缀或提交 `.env`。本机 `.env` 已加入忽略规则。
2. `npm run mcp:inspect` 列出实际工具 schema。无参数时只调用 `tools/list`；可选业务查询仅允许门店、菜单、餐品详情和算价四类只读操作。
3. `npm run mcp:check -- 上海 人民广场` 验证门店→菜单→餐品详情→算价。该命令只读，不调用创建订单；城市与地标是测试位置，可换成自己的查询位置。
4. `npm run dev` 启动后，在游戏完成一道对应料理，点击“看看对应的麦当劳餐品”，输入城市和附近位置，选择营业门店，再获取价格。核对实际商品、门店、标准配方、合计和取餐方式后，点击确认才会创建待支付订单。

`server/mcp.mapping.json` 已根据官方工具清单与实际响应配置。到店业务使用 `orderType=1`、`beType=1`，不传 `beCode`；菜单价格单位为元，算价单位为分。菜单按分类中的商品编码筛选 `data.meals` 对象，避免展示未上架商品。默认特调同时保留选中项的 `selectedKey` 和必要未选中项的 `unselectedKey`，算价与创建订单使用相同配置。

`catalogTags` 按实际商品编码或精确商品名匹配游戏料理。游戏出锅统一为巨无霸，使用 `big-mac` 标签；默认按菜单中的精确名称“巨无霸”匹配，不把双层吉士汉堡或套餐替换成巨无霸。当前门店没有对应商品时，界面显示暂无对应餐品。商品和价格以门店可售菜单及算价结果为准。`arguments` 中的 `{"$ref":"路径"}` 引用服务端保存的上下文，所有调用还会经过官方 `tools/list` 输入 schema 验证。前端不能选择工具名或覆盖上游参数。

官方文档入口：https://open.mcd.cn/mcp/doc 。官方服务地址：https://mcp.mcd.cn 。协议、工具或菜单变化时，重新运行只读检查并更新映射。

## 订单可靠性

- 报价保存在服务端内存中，5 分钟有效；客户端只提交报价编号，不允许自行传入商品价格、MCP 工具名或任意订单参数。
- 每份报价最多创建一次订单；并发确认、相同请求编号、不同请求编号重复确认都复用原订单。
- 调用外部创建订单前，先将 `unknown` 状态写入 `server/data/orders.json`；收到确认结果后再原子更新。异常、超时或进程崩溃后不会盲目重试创建订单。
- 本地订单记录在重启后保留；报价未下单前重启会失效。`GET /api/orders/:id` 或 `GET /api/order-status?quoteId=...` 读取本地记录，目前没有对未知订单或支付状态进行官方查询工具的自动同步。
- 不要删除未知状态的订单记录来“重试”。先在麦当劳官方渠道核对是否生成订单。
- 当前实现面向本地比赛演示或受控的单实例部署。公开多人部署前需加入用户身份绑定、按用户隔离的报价与订单权限、共享数据库事务和请求限流；当前无用户账号系统。

## 离线验证

`npm test` 验证游戏逻辑和服务端集成：演示完整流程、过期/伪造报价、客户端价格篡改无效、取餐方式验证、并发下单只调用一次、未知结果不重试、重启后订单去重，以及通过内存模拟 MCP 验证官方字段映射、默认特调和价格换算。测试不使用 `.env` Token，不连接真实 MCP，也不创建真实订单。

`npm run build` 执行 TypeScript 检查和生产构建。

依赖：`express`（v5）、`dotenv`、`@modelcontextprotocol/sdk`、`ajv`；开发依赖 `tsx`、`@types/express`、`@types/node`。
